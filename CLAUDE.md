# TNT Run — s&box

Multiplayer arena game. Players run across a tiled floor; every tile they step on
collapses after a fraction of a second. Fall through and you land on the floor below.
Fall past the last floor into lava and you're out. Last player alive wins the round.

Target: 24 players, auto-matchmaking, ranks. **None of that is in scope yet** — see Scope below.

## Constants (single source of truth)

Put these in one static class. Do not scatter magic numbers.

```csharp
public static class Arena
{
    public const int   GridSize      = 30;    // tiles per side, per floor
    public const float TileSize      = 56f;   // world units (s&box unit ≈ 1 inch)
    public const float TileThickness = 12f;
    public const int   FloorCount    = 8;   // 5 until 2026-10-05; KONTEKST.md asks for eight

    public const float DecayDelay    = 0.6f;  // seconds from step-on to disappear

}
```

Scale: Citizen is ~72 units tall, so a 56-unit tile is roughly a Minecraft block relative
to the player. 30×30×8 = 7200 tiles.

## Architecture — three decisions that are not negotiable

These exist because the naive version does not survive 4500 tiles × 24 players.

**1. Tiles are disabled, never destroyed.**
`GameObject.Enabled = false` on collapse. Round restart is one loop re-enabling everything.
Destroying and respawning 4500 GameObjects per round will stall the game.

**2. Tile lookup is arithmetic, not a trace.**
Never raycast down every frame to find the tile under a player. Compute it:
`tileX = (int)((pos.x - originX) / TileSize)`, same for Y, and derive the floor index from Z.
O(1), zero physics cost. Store tiles in `GameObject[,,]` indexed `[floor, x, y]`.

**3. Tile collapses are batched into one RPC.**
Do **not** put `[Sync]` on tiles. The host is authoritative: it accumulates collapsed tile
indices in a buffer and flushes them via a single `[Rpc.Broadcast]` every ~100 ms as a
packed array. Per-tile RPCs at 24 players is hundreds of messages per second.

## Components (build in this order)

| # | Component | Responsibility | Done when |
|---|---|---|---|
| 1 | `ArenaGenerator` | Builds `FloorCount` grids of tiles + lava plane at runtime. Holds `GameObject[,,]`. Exposes `GetTile(floor,x,y)` and `ResetAll()`. | Play mode shows 5 stacked floors of boxes |
| 2 | `TileDecay` | Tracks pending collapses, disables tiles after `DecayDelay`, feeds the RPC buffer. | Walking leaves a trail of holes |
| 3 | `TntPlayer` | Movement (`CharacterController`), maps world position → tile index, marks tiles as stepped-on. | Player falls to the floor below |
| 4 | `LavaZone` | Trigger below the last floor; marks player eliminated. | Falling all the way out eliminates you |
| 5 | `RoundManager` | Round state machine (Waiting → Playing → Ended), spawns players, detects last-alive, resets arena. | Rounds start and restart cleanly |
| 6 | Networking pass | Host authority, player spawn/ownership, batched collapse RPC. | Two clients see the same holes |
| 7 | `Hud.razor` | Alive count, round timer, your floor number. | — |

Stop after each numbered item and let me test it. Do not build ahead.

  colliders, the tower colliders, lava, light. That takes ~0.2 s. The surfaces then paint on worker
  threads (half the hardware threads), and `PumpBuild` uploads a few per frame. It builds the facade
  first (all the menu sees), then each room top-down as its surfaces arrive. Reflection probes switch

- Texture memory is ~408 MiB, accepted (spec amended). Published games compile in release mode, so
  the bake costs 4.3 s of CPU there against 11 s in the editor's debug build.

## Working style

- **One component per turn.** Write it, explain what to test, stop.
- **Ask before inventing.** If a design detail is undefined (e.g. what happens when two
  players stand on the same tile), ask rather than picking silently.
- **Compile errors come from me.** I paste s&box console output; that's the only feedback
  channel you have. Assume nothing compiled until I confirm it.
- **No defensive scaffolding.** No try/catch around normal logic, no null-checks on things
  that can't be null, no config systems for constants that live in `Arena`.
- Code lives in `code/`, Razor UI in `code/ui/`.
